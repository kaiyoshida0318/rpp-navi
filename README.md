# 楽天RPP 20円広告 予算ナビ v3

楽天RPPの「**全体CPC上限20円広告**」の暴走（実績額が跳ねてROASが落ちる状態）を、
前日確定データと当日3回の観測で逐次的に抑えるための予算ナビゲーションツールです。

- **サーバー不要・外部送信なし。** 単一のHTMLファイルがブラウザの中だけで動きます。
- 取り込んだデータは**各自のブラウザ内（IndexedDB）にのみ**保存されます。他の人には見えません。
- すべての判定に「なぜそう言えるか」と「判定信頼度」が表示されます。

### 最初にすること

1. 上のURLを開く

3. **ダッシュボード**タブで本日の日タイプ・危険度・推奨上限・開始予算を確認

詳しい操作は **[docs/user-guide.md](docs/user-guide.md)**（[PDF版](docs/user-guide.pdf)）を読んでください。

立ち上げ2か月のチェックリストは **[docs/checklist.html](docs/checklist.html)** です。

### 知っておくべきこと

| | |
|---|---|
| **データの保存先** | 各自のブラウザ内のみ。PCを替えると引き継がれません |
| **PC・ブラウザを移るとき** | 設定タブから **JSONエクスポート** → 移動先で **JSONインポート** |
| **20円ROASの目標** | 400%が理想 ／ 300%が防衛ライン ／ 200%割れは明確な失敗 |
| **観測時刻** | 9:30 ／ 15:00 ／ 18:30 の3回。予算提案は¥5,000刻み |
| **「意図的停止」** | 失敗ではなく正式な推奨です。「追加しない」とは別扱い |

> ⚠️ **注意：ブラウザの「閲覧データを削除」でサイトデータを消すと、記録も消えます。**
> 定期的に設定タブからJSONエクスポートしてバックアップを取ってください。

## 中身をいじる人はこちら

### 構成

```
index.html          ← ツール本体。GitHub Pagesが配信するファイル。直接編集しない
src/
  build.sh          ← b3/ を連結して index.html を作り、JS構文を検査する
  b3/               ← 分割ソース。編集はここ
docs/
  handover.md       ← 引き継ぎ書。実データから判明した事実と過去のバグ。最初に読む
  spec-v3.md/.docx  ← 開発仕様書（.docx が正典）
  user-guide.md/pdf ← 利用者向け説明書
  checklist.html    ← 立ち上げ2か月チェックリスト
data/               ← 5〜8月の実データ・イベント日程・カレンダー画像
tests/              ← Playwrightによる検証スクリプト
```

分割の理由は、1ファイルが大きすぎて編集ツールが扱いにくいためです。

| ファイル | 中身 |
|---|---|
| `p1_head.html` | CSS（テーマ変数、カレンダー、タイル） |
| `p2_body.html` | 8タブのHTML骨格 |
| `p3_core.js` | 共通関数、ZIP展開、XLSX読取、保存、`CFG_DEF`、`DB` |
| `p4_ingest.js` | ファイル取込と集計（`applyObs()` を含む） |
| `p5_logic.js` | 日タイプ判定、基準値、朝プラン、当日判定、バックテスト |
| `p6_ui1.js` | 共通UI部品、ダッシュボード |
| `p6b_ui2.js` | 当日チェック、4か月カレンダー |
| `p7_ui3.js` | イベント／履歴／バックテスト／取込／設定、起動処理 |

### ビルド

```bash
bash src/build.sh     # → index.html を生成し、JS構文を検査
```

**`index.html` を直接編集しないでください。** 次回のビルドで上書きされます。

ソースを変更したら `bash src/build.sh` を実行し、生成された `index.html` も一緒に
コミットしてください。GitHub Pagesはリポジトリ内の `index.html` をそのまま配信するため、
コミットし忘れると変更が反映されません。

> **注意：同じGitHubアカウントで別リポジトリにこのツールをもう1つ公開しないでください。**
> Pagesはどちらも `https://ユーザー名.github.io` という**同じオリジン**で配信されるため、
> IndexedDB（`rpp_tool_v1`）を共有してしまい、記録が混ざります。
> v4などを並行公開する場合は `p3_core.js` の `DBNAME` を変えてください。

### 検証

```bash
npm i playwright && npx playwright install chromium
cd tests && node t3.js      # 取込〜全画面の通し確認、カレンダー画像との突合
                node vfy.js  # 当日判定8ケース
                node bf.js   # 「後日まとめて入力」モード
                node q3.js   # 上限到達日のバイアス方向の確認
```

詳細は [`tests/README.md`](tests/README.md)。

### 触る前に必ず読むこと

**[docs/handover.md](docs/handover.md)** に、仕様書には書かれていない
「実データから判明した事実」と「過去に踏んだ11個のバグ」がまとまっています。
これを読まずに作り直すと同じ間違いを繰り返します。特に：

- **20円側 = 商品別RPPレポート − キーワード別RPPレポート**（この引き算を間違えると全部狂う）
- カレンダーの上段％は**20円ROAS**、下段％は**比率**（CVRではない）
- 予算上限到達日の除外バイアスは**両方向にぶれる**（「必ず過大になる」は誤り）
