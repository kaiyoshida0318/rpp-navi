## 3. 「20円広告」の定義（**ここを間違えると全部狂います**）

楽天のRPPレポートには「全体CPC上限20円で配信している分」を直接出す画面がありません。
そこで次の引き算で求めています。

```
20円側 = 商品別RPPレポート － キーワード別RPPレポート
```

- 実績額・クリック・売上・件数すべてこの引き算で出す
- 5〜8月の115日すべてで**マイナスが1件も出ないこと**を確認済み（＝定義として妥当）
- ユーザーの月次KPI表・カレンダー画像4枚（`calref_*.png`）と**完全一致**を確認済み

### アトリビューション期間
- 既定 **720時間**。ユーザーの月次KPI表がこの期間で作られているため。
- 12時間に切替可能（設定タブ）。ただし切り替えると数字が変わるので、比較時は揃えること。

### カレンダー表示の意味
ユーザーの実カレンダー画像を読み解いた結果：
- 上段の％ = **20円ROAS**（RPP全体ROASではない）
- 下段の％ = **比率**（CVRではない）

v1ではここを両方とも間違えて実装していました。**再確認せずに変えないこと。**

## 4. 実データから判明した事実（仕様書には書かれていない）

1. **XLSXの灰色セル＝予算上限到達**
   `xl/styles.xml` の cellXfs → fillId → patternFill を読んで判定しています。
   灰色の日はその後の消化が必ず止まっているため、データ自体から裏が取れています。

2. **予算上限に到達した日は消化カーブの学習から丸ごと除外**（設定 `capExclude:'day'`／精度優先／ユーザー確認済み）
   バイアスの向きは一方向ではありません：
   - その枠**より前**に上限到達 → 観測値が抑えられ、進捗率が**過小**
   - その枠**より後**に上限到達 → 最終額が抑えられ、進捗率が**過大**

   同梱データの18:30枠では 56.8%〜85.4% とばらつきました。
   **（前のチャットで一度「必ず過大になる」と誤って説明し、訂正済みです。繰り返さないこと。）**

3. **朝の警戒ルール v1 の性能**（同梱データで再現済み）
   条件：`前日20円実績 ≥ 30,000円` **OR** `前日20円ROAS < 225%`
   - 捕捉率 85% / 88% / 88%（<300% / <200% / <100%）
   - 仕様書の主張値（82% / 91% / 90%）とのズレは、欠測日の隣接処理の違いによるもの
   - 閾値スイープ結果：30,000円のときROAS条件が捕捉率を12pt上げる（73%→85%）。
     175%〜225%は結果が同一なので、**225%は平坦域の上端**。250%は誤警報だけが増える。

4. **18:30枠の信頼度が「低」のままな理由**
   19時→18:30のズレではなく、**8件中6件が上限到達日に当たっているから**です。
   上限未到達の平日を記録すれば解消します。

5. **19時の記録は18:30の基準に使ってよい**（ユーザー確認済み）。15時は今後蓄積予定。

## 6. 直近で追加した「後日まとめて入力」モード

**背景：** 土日など、その場でツールに入力できない日がある、というユーザーの相談。

**仕様：**
- 当日チェックタブの `後日まとめて入力` ピルをONにすると、
  保存ボタンが「観測だけ保存（提案は記録しない）」に変わる
- 観測は日付どおりに保存され、消化カーブの学習にそのまま使われる
- **提案・実行履歴には記録しない**

**なぜ分けたか：** 通常モードで後追い入力すると「実際には出していない提案」が履歴に溜まり、
後で「どの判断が20円ROASの防衛に効いたか」を見るときに数字が濁るためです。

**検証済み（`40_検証スクリプト/bf.js`）：**
```
通常入力後 : obs+1 / props+1
後日入力後 : obs+1 / props+0   ✓
```

## 7. ユーザー（KAI さん）について知っておくべきこと

- 楽天の店舗運営者。RPPの20円広告の暴走（実績額が跳ねてROASが落ちる）を止めたい。
- **全体20円しか出ていない低ROAS商品は月1のルーティンで既に広告削除済み**。
  なので「そういう商品が残っている前提」の機能を作っても意味がありません。
- 判断の根拠が見えないブラックボックスを嫌います。
  **すべての判定に「なぜそう言えるか」を表示すること**は仕様書の必須要件です。
- 閾値はすべて設定タブから編集可能である必要があります（固定値の埋め込み禁止）。
- 目標：20円ROAS **400%が理想 / 300%が防衛ライン / 200%割れは明確な失敗**。
- 日タイプ別推奨上限：通常7万 / 5の倍数9万 / セールのみ9万 / セール＋5の倍数12万 / セール最終日7万。
- 観測時刻は 9:30 / 15:00 / 18:30 の3回。予算提案は**¥5,000刻み**。
- **「意図的停止」は一級の推奨**です。「追加しない」とは別扱いで、弱めてはいけません。
